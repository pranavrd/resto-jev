# 0030: Evals in CI

- **Status:** Accepted. The workflow is written and checked locally; it has not run on GitHub (no remote).
- **Date:** 2026-10-05
- **Files:** `.github/workflows/ci.yml`, `docs/ci.md`, `tests/test_published_numbers.py`, `chat_eval.py --rescore`, `typesafe-sdk` added to `pyproject.toml`

## What it does

Lint, the web checks, and the whole Python suite on a Postgres built from `db/Dockerfile` and migrated from scratch, plus a step that fails if `data/`, `docs/private/` or `.env` is tracked. The evals that can run without a model run as tests: retrieval on invented data, the chat's guards and checks with scripted models, the instruments of the evaluation sets, and a test that recomputes every figure published in decisions 0025 to 0029 from the committed run files. Details and the list of what stays local are in `docs/ci.md`.

## What was found while setting it up

- **`typesafe-sdk` was imported but not declared** in `pyproject.toml`; a clean install would have failed. Declared.
- **The suite passes on an empty database** (340 passed, 23 skipped), so the migrations apply from scratch and no test silently depends on local data; the 23 skips are tests that need the real database, labels or a model.
- **A published number was wrong by one under the final scorer:** the first draft of planner p2 on the dev questions was logged as 23 of 32, which was true under the first scorer and is 24 of 32 under the current one (the scorer fix is in decision 0029). The test records both.

## Limits

- **Model evals are not in CI.** Prompts and models can regress without CI noticing; the guard is the read-once and fresh-set rules, and the published-number test, which catches changes to the scoring code but not to model behaviour.
- **Not verified on GitHub.** Action versions are major tags, not pinned hashes; pin them if the repository becomes public.
- **No secrets and no Yelp data are used or needed**, by construction: the tests build their own invented world and roll it back.
